the Veil

Microsoft Store reviewer instructions

Updated October 11, 2026

nl-veil is a native x64 AI coding desktop app. Use Windows 10 build 19041 or later with an OpenGL 3.3-capable graphics driver. The desktop workspace opens without an AI-provider account.

Model setup

In Settings, choose a local model through Ollama or the built-in engine, or connect your own hosted provider. Model weights are a separate download and are not bundled. Local inference does not require a Veil subscription. Hosted providers may charge for usage. No provider credentials or test accounts are included in the package.

Python must be on PATH for Python coding tools. Some JavaScript checks use Node.js. Start the installed app normally so it inherits the standard Windows environment. Close a portable Veil instance first to avoid a port conflict.

Suggested checks

  1. Launch nl-veil from Start, open Settings, change a setting, and save it.
  2. Close and reopen the app; confirm the setting persists.
  3. Connect a model and create a fresh conversation.
  4. Ask for a small Python file with an addition function and a simple assertion. Review the generated file and run its test.
  5. Reopen the app and confirm the generated file and model setup remain available.

Store runtime

The app needs runFullTrust for its native UI, bundled Neuron memory subprocess, and user-requested development commands. Agents access projects the user opens. Core operation does not require administrator rights. Store installations keep writable state in the package's per-user LocalState folder and receive updates through Microsoft Store.

Cloudflare ready: users may connect their own Cloudflare account for optional Workers AI, backups, and cloud tasks. These features are optional and may incur Cloudflare usage charges.

Certification kit findings

The optional Archive files usage check can flag cloud/gary-source.tar.gz. This is corresponding source for the optional AGPL Gary runtime, not an executable archive unpacked and launched on the host. The optional Blocked executables check can flag the bundled Neuron subprocess and user-requested development commands. Windows in S mode is not supported.

Microsoft describes these Desktop Bridge optional checks as informational in its certification guidance. App-specific results and remaining verification limits should be assessed against the exact submission build.
