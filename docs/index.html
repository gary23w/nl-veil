Open the app

  • Microsoft Store. Select Get, then open nl-veil from Start.
  • Windows ZIP. Choose Extract All, then open veil.exe in the extracted folder.
  • Mac or Linux ZIP. Extract the ZIP, open a terminal in the extracted folder and run ./start.

Use a folder you can write to. Keep bin/ and veil-install.txt beside the executable.

Set up your first chat

Open Settings → Models. For local AI, select Download the-veil-12b (~7 GB), then Use built-in for chat. You can also select a running Ollama model or connect a hosted provider.

Open Chat and send Reply with Veil is ready. When you are ready to edit a project, the coding tools use Python on PATH. Some JavaScript checks also use Node.js.

System requirements
  • Windows. The Store package requires Windows 10 version 2004 or later. Windows 11 on Arm can emulate x64 apps. Windows on Arm details
  • Mac. Choose the build for your chip and use macOS 13 or later. Identify your Mac
  • Linux. Use an x86-64 desktop with glibc 2.39 or later (such as Ubuntu 24.04), X11 or XWayland, and OpenGL drivers. Run uname -m and ldd --version to check your architecture and glibc. Install curl for app updates.
Verify a ZIP download

Compute the SHA-256 of the downloaded ZIP, then compare it with the line for that filename in its checksum file.

  • Windows PowerShell Get-FileHash -Algorithm SHA256 .\filename.zip · Windows checksum
  • macOS Terminal shasum -a 256 filename.zip · Apple silicon checksum or Intel Mac checksum
  • Linux terminal sha256sum filename.zip · Linux checksum
Download or launch problems
  • Download failed. Retry from the official releases, or use Microsoft Store on Windows. On GitHub, choose the ZIP for your platform in the latest release.
  • Windows SmartScreen or macOS Gatekeeper. The ZIPs are unsigned. On Windows, Microsoft Store provides the signed install. On macOS, Apple explains how to open an app from an unknown developer after you verify its source. If your device is managed, contact your administrator.
  • Open Terminal in the extracted folder. Type cd followed by a space, drag the folder into Terminal and press Enter. Then run ./start.
  • Terminal says permission denied. From the extracted folder on macOS or Linux, run chmod +x start veil bin/neuron, then ./start.
  • Need help? Include your platform, the ZIP filename and the error in the project issue tracker.
Update an existing install

For a Store install, use Microsoft Store updates. For a ZIP install, finish active work and open Settings → Updates → App updates → Update & restart. If your copy predates the updater or cannot start, use the manual update and recovery guide.

Taters

Taters: the tool tree and Gary’s 4tope, running in your cloud.

Past 48 tools a tater’s belt is a map it walks with one verb, a long step is folded into a net instead of cut, and each model’s quirks are learned and healed as they show up.

Walk the map in the cloud

The built-in belt stays listed; Agent Garrett’s catalogue is a map of families and groups. The step’s own words open the right group first, and the words that led to a tool are learned for next time.

/belt auto|map|flat chooses how a tater sees its tools.

Fold, don’t cut

A step that outgrows its model’s window keeps the results it rests on and lays the rest out as NEXT, ON DISK, RULED OUT and ESTABLISHED, verbatim. The same net carries into the next iteration.

Heal per model, revert any edit

A model that needs more room gets it first; one that goes silent hands the day to a fallback. A runtime edit that fails to deploy is flagged and can be reverted, and a newer veil’s runtime arrives as a revision.

Gary’s 4tope

Gary’s 4tope: long chats, kept whole by graph theory.

When a turn has to compact, the engine reads its working log as a dependency graph. The longest path back from the current step is what the work rests on, and it is never pruned. The rest is carried along a shortest-path tree, in the turn’s own words, with no model call and no summary.

The tool tree turns the tool belt into a map the model walks seven branches at a time, so even a small model can use hundreds of tools.

Keep the critical chain

L(v) = max{ L(u) + w(v,u) : u ∈ deps(v) }

One linear pass, because every dependency points at something older. Followed from the current step, it names the results nothing may trim away.

Carry the shortest-path tree

d(v) = min{ d(u) + c(u,v) : u ~ v },  d(f) = 0

Dijkstra from the current step under a byte budget, laid out along the tree so each derivation reads as one run: NEXT, ON DISK, RULED OUT, ESTABLISHED.

Walk the tool tree

One verb, open_tools, seven branches per view. The engine opens the likeliest group before the first call, a tool the model already knows opens its own branch, and the map learns which words lead to which tools.

Opt-in with NL_TOOL_MAP=1. Agent Garrett, plugins and MCP servers attach as branches of their own.

Questions

The short answers.

What is the Veil?

The Veil (nl-veil) is a free, open-source desktop app for building software with AI, under the MIT license. You give it a goal in a native three-pane workspace. It can split the job across a team of specialist agents, each owning real files, working in parallel on one shared memory, and it carries what it learns about your project into the next session. It runs on Windows, macOS and Linux.

Does it need an API key or an account?

Not for local models. The built-in model, the-veil-12b, is served by the app itself, and Ollama runs on your own machine; neither needs a provider account or an API key. The model weights are a separate download: open Settings → Models and select Download the-veil-12b (~7 GB), or run veil model pull. A hosted provider you connect has its own account, key and costs.

Which models does it run?

Its built-in engine serves the-veil-12b from a GGUF file on disk, with no separate model runtime. It also works with a local Ollama, any OpenAI-compatible endpoint, and, once you log in with Cloudflare, your own account’s Workers AI models. Each turn’s calls are labelled coding, thinking or prompting, and each role can use a different model.

What does my machine need?

The download for your platform: Windows x86-64 (the Store package needs Windows 10 version 2004 or later), macOS 13 or later on Apple silicon or Intel, or Linux x86-64 with glibc 2.39 or later. The coding tools need Python on PATH, and some JavaScript checks use Node.js; if Python is missing, the agent can install it itself. The built-in engine uses your GPU through Vulkan when there is one and falls back to the CPU; macOS builds run it on the CPU. Hardware needs depend on the model you choose.

Where does my data go?

Local conversations, keys and memory are stored in a data/ folder next to the app. Hosted model calls, web tools and optional Cloudflare backups send the data those features need to the services you connect. The app itself has no analytics. The details are in the privacy policy.

What should I try first?

Pick a model, open a small project you can safely edit, and ask for one concrete change: find a missing input-validation test, add it, make the smallest fix and run the tests. Review the diff and the test output. Then start a new conversation on the same project and ask what test command you used and what changed last time.

    A cast, reconstructed

    From one typed line to a booted deliverable.

    What the engine actually did on one ordinary evening. The chips open the module that did it.

    1. 21:12

      The goal arrives: one line, typed at the desk. The gateway checks the key at the door, and the audit log writes down the knock before anything answers it.

    2. 21:13

      The supervisor detaches a worker. Casts run as separate processes; a cast survives the server that started it, the way a boat survives the dock.

    3. 21:14

      The blueprint is drawn. The goal declares its file tree and every file gets an owner; no mind writes a teammate’s slice. Eleven minds open one shared memory and begin.

    4. 21:20

      A write misses. The failure is recorded with its exact path before anything else happens. The fix comes later; the record comes first.

      The miss is written down before the fix. That order is the whole method.
    5. 21:26

      Edits from eleven minds meet in one file. Disjoint regions merge on their own. The same region is a conflict, and conflicts are said out loud, never papered over.

    6. 21:31

      The checkpoint is rebuilt from the record: what completed, what’s blocked, what’s pending. No model is asked for its opinion — the ledger already knows.

    7. 21:33

      Out of band, a reviewer reads the round’s real tool trace and mints a lesson into the live hive — only what the trace can ground, nothing a mind merely claimed.

      A lesson nobody typed. It came off the trace.
    8. 21:38

      The crawler brings back the outside. A fetched fact enters the hive only with a verbatim quote from the page that said it; the rest stays outside where it belongs.

    9. 21:40

      Smoke test. The deliverable is booted and probed, not admired. Passing tests are not a working app; a working app is a working app.

    10. 21:55

      The judge scores the cast. The governor reads the fitness curve, trims what idles, keeps what moves. A plateau is information, not failure.

      The score is not the goal. Read the curve.
    11. 22:05

      Collection. Files, the event stream, the metered spend, and the record of what was actually verified against what was merely assumed.

    12. —

      No cast is closed until somebody reads the record.

    The memory underneath

    The hive remembers in neuron-db.

    Every observation any mind makes — a crawled fact, a failure with its path, a judge’s score — lands in one associative store that every other mind can reach. That store is its own project, and it runs without nl-veil.

    One shared memory

    Separate memories made polite strangers; one shared memory made a swarm. No private notebooks — the crawler’s facts, the builder’s failures and the judge’s scores all land where every mind can reach them.

    In the engine: worker/oscillation.zig and worker/neuron/client.zig, both fail-open — if the store is down, the cast keeps running.

    neuron-db, standalone

    A typed-neuron associative store in Rust: recall in milliseconds over a million facts, plasticity that strengthens only what the evidence supports, and a browser build that runs the real core in WASM.

    How it is built

    Four rules the engine is held to.

    Not marketing copy — these are the constraints the code is reviewed against.

    The engine is a floor, not a script

    It never learns what a goal means; it learns how goals move. The day a use case gets hardcoded into the loop is the day the loop stops deserving the name.

    Every mechanism is general. A branch in the engine that knows what it is building is a bug report.

    A mind that shares is worth six that don’t

    One hive, no private notebooks. Every observation any mind makes lands where every other mind can reach it — and that is measurable, not a slogan.

    Tool availability depends on the configured integrations.

    Nothing mints but the trace

    Outcome feedback strengthens what exists; it never creates what doesn’t. A win saturates a memory — it does not invent one, and a finished goal never comes back from the dead because a reward said it should.

    Plasticity is a privilege of evidence.

    A score is not the truth

    A benchmark says the score is high. The smoke test says the app boots. Those are different sentences, and the engine pays the difference on every cast.

    Knowing isn’t proof. The ledger records what was verified against what was merely assumed.
